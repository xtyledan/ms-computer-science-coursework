<h1 align="center"> AI Security, Transparency, and Code Reliability</h1>

## Learning Objectives

By the end of this module, the following objectives are demonstrated:

- Identify the security and transparency risks associated with AI in different domains
- Analyze the security and transparency risks of code-generating AI tools

## Module Overview

Artificial intelligence has become a powerful tool for generating code, automating repetitive tasks, and improving software development productivity. While AI coding assistants can rapidly produce functional code, they do not fully understand software architecture, security best practices, or the specific requirements of every project. As a result, AI-generated code should always be carefully reviewed before being used in production environments.

One of the greatest concerns surrounding AI-generated code is **security**. AI models may generate vulnerable code, recommend insecure programming practices, or suggest outdated libraries and dependencies that contain known security flaws. Because AI systems generate responses by identifying patterns in their training data rather than reasoning like experienced software engineers, they can unintentionally introduce bugs, security vulnerabilities, or inefficient implementations.

Another important challenge is **transparency**. Most AI developers do not publicly disclose the complete datasets used to train their models, making it difficult to determine where generated code originates or whether it could contain licensing, security, or reliability concerns. This limited visibility requires developers to independently verify AI-generated code rather than assuming it is correct or secure.

Throughout this module, you will examine the security and transparency risks associated with AI-powered development tools while learning how to critically evaluate AI-generated code. By combining AI assistance with careful human review, developers can improve productivity while maintaining software quality, security, and reliability.
